Mi az Ansible?

A lényeg egyszerűen

Az Ansible egy agentless automatizálási eszköz, ami azt jelenti, hogy a hálózati eszközökre semmit nem kell telepíteni. A vezérlés SSH-n (vagy NETCONF-on) keresztül történik, közvetlenül a meglévő protokollokat használva.

💡
Egy mondatban:

Ansible = Emberi nyelven megírt utasítások, amiket automatikusan végrehajt sok eszközön egyszerre.

🚫

Nincs agent

Nem kell semmit telepíteni a switchekre, routerekre. SSH elég.

📖

Olvasható szintaxis

YAML formátum — közel annyira érthető, mint egy angol mondat.

🔁

Idempotens

Futtathatod 10x — csak az fog változni, aminek változnia kell.

📦

Moduláris

Cisco IOS, NX-OS, ASA, Juniper — mind elérhető modulokkal.

Mire használjuk hálózatnál?

  • VLAN-ok konfigurálása egyszerre 50 switchen
  • Interface leírások tömeges frissítése
  • ACL-ek, routing protokollok deploy-olása
  • Konfiguráció backup és compliance ellenőrzés
  • NTP, DNS, AAA beállítások egységesítése
  • Változások dokumentálása (mi változott, mikor, ki futtatta)

Inventory — Az eszközlista

Kinek adjuk ki a parancsokat?

Az inventory megmondja az Ansible-nek, hogy mely eszközöket kell elérni. Két formátum létezik: INI és YAML. Hálózatnál a YAML ajánlott, mert több opció fér el tisztán.

INI formátum (egyszerű)

INI — inventory/hosts.ini 
# Core réteg switchek
[core_switches]
core-sw01 ansible_host=10.10.1.1
core-sw02 ansible_host=10.10.1.2

# Access réteg switchek
[access_switches]
acc-sw01  ansible_host=10.10.2.1
acc-sw02  ansible_host=10.10.2.2
acc-sw03  ansible_host=10.10.2.3

# Minden switch együtt
[all_switches:children]
core_switches
access_switches

# Csoportos változók
[all_switches:vars]
ansible_network_os=cisco.ios.ios
ansible_connection=network_cli
ansible_user=admin
ansible_ssh_pass={{ vault_ssh_pass }}

YAML formátum (ajánlott)

YAML — inventory/hosts.yml 
all:
  children:
    core_switches:
      hosts:
        core-sw01:
          ansible_host: 10.10.1.1
        core-sw02:
          ansible_host: 10.10.1.2
      vars:
        ansible_network_os: cisco.ios.ios
        ansible_connection: network_cli

    access_switches:
      hosts:
        acc-sw01:
          ansible_host: 10.10.2.1
        acc-sw02:
          ansible_host: 10.10.2.2
✅
Tipp: inventory tesztelése

Futtasd le: ansible-inventory -i inventory/hosts.yml --list — megmutatja az összes eszközt és csoportot JSON formában.

Playbook — A recept

Mit csináljon az Ansible?

A playbook egy YAML fájl, amiben play-ek vannak. Minden play megmondja: ezen az eszközcsoporton, ezeket a feladatokat hajtsad végre.

Playbook anatómia

YAML — vlan_deploy.yml 
---
# Ez a "play" fejléce:
- name: VLAN-ok konfigurálása az access switcheken   # Leírás
  hosts: access_switches                              # Kiken fut?
  gather_facts: false                                 # Hálózatnál mindig false

  vars:                                                # Helyi változók
    vlans_to_configure:
      - { vlan_id: 10, name: Management }
      - { vlan_id: 20, name: Data }
      - { vlan_id: 30, name: Voice }

  tasks:                                               # A feladatok listája
    - name: VLAN-ok létrehozása                       # Task neve (logban látszik)
      cisco.ios.ios_vlans:                             # Melyik modult használjuk
        config:                                        # A modul paraméterei
          - vlan_id: "{{ item.vlan_id }}"
            name: "{{ item.name }}"
            state: active
        state: merged
      loop: "{{ vlans_to_configure }}"                 # Végigmegy a listán

    - name: Konfiguráció mentése
      cisco.ios.ios_command:
        commands: write memory

A YAML szintaxis alapjai

Behúzás = struktúra

2 szóköz = egy szint. Tab TILOS. Ez a leggyakoribb hiba!

--- a fájl eleje

Minden YAML playbook ezzel kezdődik — jelzi, hogy lista következik.

- listaelem

Kötőjel + szóköz = új listaelem. Tasks, hosts, vars mind lista.

{{ változó }}

Jinja2 template — dinamikus értékek. Idézőjelbe kell ha a sor elején van.

⚠️
Leggyakoribb YAML hiba

Tab karakter behúzásban. VSCode-ban állítsd be: Spaces: 2 a státuszsorban, és kapcsold be a "Render Whitespace" opciót.

Változók kezelése

Adatok és titkok elválasztása

A változókat soha ne hardcode-old be a playbookba — különösen jelszavakat. Az Ansible-nek van egy titkosítási rendszere: az Ansible Vault.

Változók prioritási sorrendje (legmagasabbtól)

Prioritás 
# 1. Extra vars (parancssori -e flag) — legmagasabb prioritás
ansible-playbook playbook.yml -e "vlan_id=100"

# 2. Task vars (a task-ban definiált vars:)
# 3. Play vars (a play-ben definiált vars:)
# 4. host_vars/hostname.yml — egy adott eszköz változói
# 5. group_vars/groupname.yml — egy csoport változói
# 6. inventory változók
# 7. Role defaults — legalacsonyabb prioritás

group_vars struktúra (ajánlott)

Könyvtárstruktúra 
ansible-cisco/
├── inventory/
│   └── hosts.yml
├── group_vars/
│   ├── all/
│   │   ├── vars.yml          # Közös változók
│   │   └── vault.yml         # Titkosított jelszavak
│   ├── core_switches/
│   │   └── vars.yml          # Core-specifikus változók
│   └── access_switches/
│       └── vars.yml          # Access-specifikus változók
├── host_vars/
│   └── core-sw01/
│       └── vars.yml          # Eszközspecifikus változók
└── playbooks/
    └── vlan_deploy.yml

Ansible Vault — Jelszavak titkosítása

Bash — Terminal parancsok 
# Vault fájl létrehozása (kér egy master jelszót)
ansible-vault create group_vars/all/vault.yml

# Szerkesztés
ansible-vault edit group_vars/all/vault.yml

# Playbook futtatás vault jelszóval
ansible-playbook playbook.yml --ask-vault-pass

# Vagy jelszó fájlból (.gitignore-ban kell lennie!)
ansible-playbook playbook.yml --vault-password-file .vault_pass
YAML — group_vars/all/vault.yml (titkosítva tárolt) 
# Nyers tartalom (vault titkosítja ezt a fájlt):
vault_ssh_pass: SzuperTitkosJelszo123!
vault_enable_pass: EnableJelszo456!

Roles — Újrafelhasználható modulok

DRY elv az automatizálásban

A role egy előre meghatározott könyvtárstruktúra, ami egy feladatot (pl. "NTP konfigurálás") önálló csomagba rendez. Egyszer megírod, mindenhol újrahasználod.

Role könyvtárstruktúra 
roles/
└── ntp_config/
    ├── tasks/
    │   └── main.yml      # A feladatok (kötelező)
    ├── vars/
    │   └── main.yml      # Role-specifikus változók
    ├── defaults/
    │   └── main.yml      # Alapértelmezett változók (felülírhatók)
    ├── templates/
    │   └── ntp.j2        # Jinja2 sablonok
    └── handlers/
        └── main.yml      # Esemény-alapú feladatok (pl. reload)
YAML — Role használata playbookban 
---
- name: Alap konfiguráció minden switchen
  hosts: all_switches
  gather_facts: false
  roles:
    - ntp_config       # roles/ntp_config/ mappa
    - syslog_config    # roles/syslog_config/ mappa
    - snmp_config      # roles/snmp_config/ mappa

Cisco Modulok

cisco.ios collection — a legfontosabbak
📦
Collection telepítése

ansible-galaxy collection install cisco.ios — ez tartalmaz minden Cisco IOS modult.

Modul Mire való? State opciók
cisco.ios.ios_vlans VLAN-ok kezelése merged, replaced, deleted
cisco.ios.ios_interfaces Interface beállítások (leírás, speed, duplex) merged, replaced, deleted
cisco.ios.ios_l2_interfaces L2 port mód (access/trunk), VLAN tagek merged, replaced, deleted
cisco.ios.ios_l3_interfaces IP cím konfigurálás merged, replaced, deleted
cisco.ios.ios_command Tetszőleges IOS parancs futtatása —
cisco.ios.ios_config Nyers IOS konfig blokkok alkalmazása —
cisco.ios.ios_facts Eszközadatok lekérése (verzió, interfacek, stb.) —
cisco.ios.ios_ntp_global NTP szerver konfiguráció merged, replaced, deleted
cisco.ios.ios_banner Login banner beállítása present, absent

State opciók magyarázata

merged

Hozzáadja, ami hiányzik. Ami már megvan, nem változik. Legtöbbször ezt használjuk.

replaced

Az adott erőforrást (pl. egy interface) teljes egészében lecseréli a megadottra.

deleted

Törli a megadott konfigurációt az eszközről.

gathered

Csak lekéri az aktuális konfigurációt, nem változtat semmit. Audit-hoz.

Teljes példa konfiguráció

Valós use-case: Access switch alap konfig

Egy access switch alap konfigurációja: VLAN-ok, interface leírások, NTP, syslog. Ez egy teljes, működő playbook.

YAML — playbooks/access_switch_baseline.yml 
---
- name: Access switch alap konfiguráció
  hosts: access_switches
  gather_facts: false
  connection: network_cli

  vars:
    ntp_servers:
      - 10.0.0.1
      - 10.0.0.2
    syslog_server: 10.0.0.100
    vlans:
      - { id: 10,  name: Management }
      - { id: 20,  name: Data       }
      - { id: 30,  name: Voice      }
      - { id: 100, name: Native     }

  tasks:
    # --- VLAN-ok ---
    - name: VLAN-ok létrehozása
      cisco.ios.ios_vlans:
        config:
          - vlan_id: "{{ item.id }}"
            name: "{{ item.name }}"
            state: active
        state: merged
      loop: "{{ vlans }}"

    # --- NTP ---
    - name: NTP szerverek beállítása
      cisco.ios.ios_ntp_global:
        config:
          servers:
            - server: "{{ item }}"
        state: merged
      loop: "{{ ntp_servers }}"

    # --- Syslog ---
    - name: Syslog szerver konfigurálása
      cisco.ios.ios_logging_global:
        config:
          hosts:
            - hostname: "{{ syslog_server }}"
        state: merged

    # --- Mentés ---
    - name: Running config mentése
      cisco.ios.ios_command:
        commands: write memory

    # --- Visszaellenőrzés ---
    - name: VLAN adatbázis ellenőrzése
      cisco.ios.ios_command:
        commands: show vlan brief
      register: vlan_output

    - name: VLAN output megjelenítése
      debug:
        var: vlan_output.stdout_lines

Futtatás

Bash — Terminal 
# Dry run — csak megmutatja, mi változna (nem hajt végre semmit!)
ansible-playbook -i inventory/hosts.yml playbooks/access_switch_baseline.yml --check

# Csak egy eszközön (teszt előtt)
ansible-playbook -i inventory/hosts.yml playbooks/access_switch_baseline.yml --limit acc-sw01

# Éles futtatás
ansible-playbook -i inventory/hosts.yml playbooks/access_switch_baseline.yml

# Részletes kimenet (debug)
ansible-playbook -i inventory/hosts.yml playbooks/access_switch_baseline.yml -v   # verbose
ansible-playbook -i inventory/hosts.yml playbooks/access_switch_baseline.yml -vvv # nagyon részletes
